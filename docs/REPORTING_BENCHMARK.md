# Reporting benchmark

Generated by `node --import tsx scripts/reporting-benchmark.ts 10000000 5000` (phase 14, step R2; see
`docs/REPORTING_STEP2.md`). Don't edit by hand: rerun the script.

**Machine:** Apple M1, 8 cores, 8 GB; PostgreSQL 17.10 (embedded, default settings), on the same machine.
**Data:** 10,000,000 parts in 5,000 workspaces (1,250,000 conversations over 120 days). Sizes are skewed:
the largest workspace has 588,784 parts, the 99th percentile workspace has 14,216 parts, the median workspace has 1,064 parts.
`a_conversations` 1250000, `a_parts` 10000000, `a_states` 2312590, `a_responses` 2125144, `a_handling` 1062590 rows.
**Method:** each chart is one `runMetric` call (the period, the previous period and the breakdown, three queries) as the runtime
role with row-level security on, timezone Europe/London. Each report's charts run one after another; one warm-up run, then 7 timed.
A report's time is all its charts in sequence (R3 can run them in parallel). The target is the codebase's rule, 200 ms at p95, per chart.

**Result:** 2 reports had a chart over 200 ms at p95 (below).
